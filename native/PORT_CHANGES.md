# Native code retained by the C# port

Source baseline: preserved `editor` commit `f7b10874d8544e0a4b4095383d85020d5c7d0c39`. `SOURCE_MANIFEST.json` describes historical upstream provenance, not current build hashes. `release-manifest.json` records published binary hashes.

- `crypto_bridge.cpp` exposes the existing `SaveWriter::ChaCha20Crypt` implementation. Bouncy Castle 2.7.0 does not publicly expose the game's arbitrary initial counter. Reusing existing code avoids private-field reflection, another cipher implementation, or another native library. Bouncy Castle is not a dependency.
- `reader_bridge.cpp` reads one selected class using the existing parser and JSON serializer. This separate DLL retains record fields without changing the streaming validator or compact relocation ABI.
- `parc_read_item_references` uses that same parser and returns only ItemSaveData records matching the selected number and key, including store stock and cached references. Top-level list records and stock records are decoded individually and retained only if they contain the requested reference; the final traversal uses the same identity matcher. Nested matching item metadata remains complete. Malformed identities are retained so the outer reader still rejects them. Managed code validates record boundaries and typed fields before using the common patch/Undo transaction.
- `SAVEULTIMATE_SELECTED_READER` enables the selected-class reader and bounds candidate list allocations. It ports the original Python reader's schema-specific absent-list marker handling for `ItemSaveData` and `FactionNodeElementSaveData`.
- Existing `parc_validation` and `parc_index` algorithms remain separate. Validation retains full-stream byte-stable serialization and write/reopen checks.
- The selected ownership reader decodes and discards each `_storeItemList` element instead of retaining the entire stock tree before omitting it from StoreSaveData JSON. Stock is not physical ownership and otherwise expands the v2.03.02 sample to 302 MB of JSON. List counts and candidate selection by decoded count/end offset remain intact, so accidentally requesting an omitted list fails the managed completeness check. Sold items remain fully represented. Reference searches retain matching stock records; the underlying decoder and full-blob validator still process all stock bytes. Retention settings are local to the parsed schema, not shared mutable state.
- Selected-reader JSON now contains only objects and the metadata consumed by `SaveRecords`; it omits indentation, duplicate schema, scalar display strings and unused diagnostic properties. Omitted zero/empty properties use the managed model's existing defaults. Diagnostic parser JSON remains unchanged.
- Runtime reader/index/validator builds skip scalar-to-display-string conversion after the same size/bounds checks. Serialization validation still reads the original typed bytes; no validation rule was removed. Inline child field vectors are moved into their owning record instead of deep-copied.
- The selected reader also skips raw-value/list-header byte copies used only for serialization. It retains offsets, sizes and parsed metadata; the full validator and diagnostic parser retain their raw bytes and serialization checks.
- Selected JSON takes ownership of the completed C++ stream string instead of copying it. Managed `SaveRecords` deserializes a read-only span over the native output; `finally` frees the buffer after synchronous deserialization or an error, avoiding a second large managed JSON buffer.
- Non-reference selected reads serialize list elements with the existing JSON writer as they are decoded, retaining one record tree at a time. The selected result releases its source blob before producing final JSON. Class metadata and JSON values were compared against the previous DLL on three saves; reference searches keep tree traversal and matching coverage.
- Streaming validation shares one scratch buffer between field and block serialization, and releases it on every parser exit, including exceptions. Thread-pool workers no longer retain two full-file buffers indefinitely. All roundtrip comparisons remain in place.
- Relocation releases its parsed source copy and object index after building checked links, before constructing the candidate. The checked links, TOC, bounds checks and unknown-pointer rejection remain unchanged.
- `parc_read_lists` decodes only requested top-level record lists at field spans supplied by the existing compact index. The managed boundary checks class/field identity, uniqueness and block bounds; the native reader checks list kinds, ordered non-overlapping spans and exact decode endpoints. This matches Python's selective quest/mission reader and avoids materializing unrelated QuestSaveData event metadata. Load, structural commit and write/reopen still run the full validator; existing reader exports retain their behavior.
- Absent selected lists fall back to the full block decoder, as in Python. The selected reader now shares the compact index's checked absent-list marker handling for ContentsMiscSaveData and FieldNPCSaveData. This preserves scalar boundaries and exposes the first-catch prerequisite in saves without a MiniGameRecordSaveData type. The full validator was not changed.

- `parc_validation` no longer links `parc_engine.cpp`; the validated writer reads the source header directly and parses the file once with the same HMAC and full validation checks. Its diagnostic JSON parse exports remain only in the `parc_parser` oracle. Unused `parc_index_blob`/`parc_block_index` exports were removed from `parc_index`.

Build with CMake 3.24+ and a Windows x64 C++20 compiler. `scripts/Build.ps1` builds the three runtime DLLs from this source. The old `parc_parser` oracle target is not published.

Native file APIs still use the Windows active ANSI code page. The managed boundary rejects paths it cannot represent instead of substituting characters. Full Unicode native-path support remains a migration task.
